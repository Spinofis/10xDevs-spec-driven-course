AppDbContext.cs — add DbSet<UserProfile> UserProfiles + DbSet<UserPreferenceTag> UserPreferenceTags

IAppDbContext.cs — add the same two DbSets

New SQL migration api/Infrastructure/Database/YYYYMMDD_add_user_profile.sql:

CREATE TABLE IF NOT EXISTS user_profile (
  user_id           uuid    PRIMARY KEY,
  default_budget_level text NULL,
  default_people_count integer NULL CHECK (default_people_count IS NULL OR default_people_count > 0),
  default_pace      text    NULL,
  default_notes     text    NULL,
  is_default        boolean NOT NULL DEFAULT true,
  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT user_profile_user_id_fk FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

Note: user_preference_tags table already exists in the initial migration.

Feature 3: User Registration (POST /auth/register)

Already fully implemented — RegisterUserCommandHandler creates a User, validates email uniqueness, saves, returns 201 {}. This matches the API plan exactly.

The one optional enhancement: after _db.Users.Add(user), also add _db.UserProfiles.Add(UserProfile.Create(user.Id)) in RegisterUserCommandHandler. This ensures GET /me/profile always has a row to read and simplifies the GET handler (no need for null-profile fallback logic). We note this as a recommended addition that keeps the Me GET handler simple.
